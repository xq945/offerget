## 2. 功能明细

### 2.1 营销首页

- Hero 区产品演示、核心能力介绍、价值主张与行动入口。
- 未登录用户引导注册 / 登录；已登录可直达工作台。
- 页脚展示技术栈与个人自用部署说明。

### 2.2 账号体系

- **注册**：用户名（3–20 位字母 / 数字 / 下划线，唯一）、密码（6–32 位）、昵称（必填）、毕业年份（可选，2024–2035）；密码经 BCrypt 加密存储。
- **登录**：校验成功后签发无状态 JWT，默认有效期 2 小时（`APP_JWT_EXPIRATION_SECONDS` 可调）。
- **鉴权**：除注册、登录与 `/uploads/**` 静态资源外，其余接口均经 JWT 过滤器校验；请求携带 `Authorization: Bearer <token>`。
- **前端守卫**：未登录访问工作台路由会跳转登录页并保留 `redirect`；已登录访问登录页会重定向到总览。
- 刷新页面后自动恢复用户信息（`/api/auth/me`），持久化登录状态。

### 2.3 校招总览

- **统计卡（4 张）**：总岗位数（含本周新增）、已投递数量（所有非「待投递」状态，含笔试 / 面试 / Offer / 未通过）、面试中数量、Offer 数量。
- **本周投递趋势**：周一到周日每日新增岗位数柱状图。
- **3 天内截止**：未来 3 天内截止的岗位，最多展示 5 条，排除 Offer 与未通过；展示匹配分。
- **今日待办**：优先展示今天的求职事件（截止 / 投递 / 笔试 / 面试 / 结果）；当天无事件时，回退为 3 天内截止的待投递岗位。
- **AI 建议**：后端规则引擎生成，最多 4 条，覆盖即将截止、今日面试、未匹配岗位、Offer 提醒及兜底建议。
- **投递台历**：按月加载求职事件，支持切换月份，事件按类型区分展示。

### 2.4 我的投递

- **岗位字段**：公司、岗位、城市、薪资范围、岗位类型、投递来源、JD 文本、截止日期、绑定简历、备注、匹配分。
- **状态流转（6 种）**：待投递 → 已投递 → 笔试 → 面试 → Offer / 未通过。
- **增删改查**：抽屉表单新增 / 编辑，删除二次确认。
- **列表能力**：状态筛选、关键词搜索（公司 / 岗位）、分页。
- **快捷入口**：岗位操作菜单可直接进入该岗位的模拟面试。
- **状态变更记录**：每次状态流转自动写入一条求职事件，供台历、待办和提醒使用。
- **联动清理**：删除岗位时同步删除该岗位的求职事件与 AI 匹配记录。

### 2.5 简历管理

- **上传**：支持 PDF / DOC / DOCX / TXT，单文件不超过 10MB。
- **文本解析**：Apache Tika 提取简历文本，用于匹配、优化与自动填充。
- **多版本管理**：每份上传简历保留版本名称与版本标签，可改名、删除、设为默认版本。
- **内容预览**：解析后的文本可在页面内查看。
- **与投递联动**：岗位可绑定某一简历版本。

### 2.6 简历制作器

- 结构化表单录入：基本信息、教育、技能、实习、项目、自我评价等。
- A4 尺寸实时预览，所见即所得。
- 通过浏览器打印导出 PDF（打印样式自动隐藏侧栏、顶栏与表单）。
- 保存为在线简历，结构化内容存于 `resume.content_json`，可直接参与 AI 匹配与定制。

### 2.7 自动填充

- 从在线简历（结构化内容）或上传简历的解析文本中提取网申字段。
- **提取字段**：姓名、手机号、邮箱、所在城市、学校、专业、学历、毕业年份、技能，以及实习 / 项目经历（组织、职位、时间、要点）。
- 支持逐项复制与一键复制全部网申信息。
- 仅做信息整理，不直接操作第三方招聘网站表单。

### 2.8 AI 匹配

- **实现方式**：本地规则引擎，不调用大模型，不上传简历内容。
- **算法**：内置 56 个技能关键词词典（后端 / 前端 / 数据 / 产品运营 / 通用），按词典权重与 JD 命中率计算得分，叠加实习、项目等经历加分。
- **输出**：匹配分（0–100）、命中关键词、缺失关键词（按权重排序，最多 8 个）、逐词补充建议、综合结论。
- **兜底**：JD 为空返回默认 50 分提示补全 JD；简历无可解析文本返回 35 分并给出上传提示。
- **历史记录**：每次匹配入库，支持查看历史与最近一次匹配，可关联岗位和简历。
- **分数回写**：匹配结果同步写入岗位的 `matchScore`，供总览、投递列表与复盘使用。

### 2.9 简历优化

- 复用 AI 匹配的技能词典，对照目标岗位 JD 找出简历缺失关键词。
- 按简历实际段落（教育背景、实习经历、项目经历、专业技能、自我评价等）生成补充建议，最多覆盖 4 个段落，命中关键词最多展示 6 个。
- 给出优化前分数与预估优化后分数。
- 优化记录持久化，支持按岗位过滤历史。
- 只生成建议，不直接修改简历内容。

### 2.10 AI 简历定制

- **依赖**：服务端配置 `DEEPSEEK_API_KEY` 后可用；未配置时该功能返回明确错误，不影响其他模块。
- **输入**：目标岗位 JD + 简历文本（在线简历或上传简历）。
- **处理**：DeepSeek 逐段改写实习 / 项目 / 技能 / 自我评价等段落，模型仅做重组与措辞调整。
- **事实校验**：改写稿与原文对比，新增技能词、新增数字、新增年份、新增强主动表述（如「主导」「从 0 到 1」）均产生告警。
- **审阅**：前端逐段展示原文、改写稿与选用理由，支持逐段 diff 查看，用户可逐段「采用 / 忽略」。
- **生成版本**：用户确认后，按采用段落总是创建一份新的简历版本，原版本保持不变。
- **分数对比**：记录改写前后的匹配分，采用段落变化时前端可实时重算展示。
- **历史记录**：定制记录持久化，支持按岗位过滤；已应用的记录标记状态。

### 2.11 AI 模拟面试

> 设计方案与取舍见 [ai-mock-interview-design.md](ai-mock-interview-design.md)。

- **入口**：工作台「求职工具」→「模拟面试」（`/app/mock-interview`）；也可从岗位操作菜单或面试 / 笔试提醒直接进入该岗位。
- **依赖**：复用现有 DeepSeek 接入（已支持多轮消息与可调温度）；未配置密钥时该功能不可用，不影响其他模块。
- **开始面试**：选择目标岗位（自动带出 JD）与简历版本（默认使用岗位绑定的简历），可选面试类型（技术面 / 行为面 / 综合面）与难度。
- **题单生成**：固定 6–7 道主问题 + 反问，结合 JD 与简历出题，覆盖自我介绍、项目 / 实习深挖、岗位技术或业务基础、行为面试；每道题带可回溯的 JD / 简历原文依据，校验失败会丢弃并重试。
- **动态追问**：每题最多 2 层追问，根据作答中的模糊点展开；跳过或明确回答「不知道」时不追问，达到上限强制进入下一题。
- **反问环节**：题单结束后可向面试官提问最多 2 个问题，AI 以该公司 / 岗位面试官身份回答；反问不计入总分。
- **沉浸模拟**：面试过程中面试官只推进对话，不给分数、点评或参考答案；所有评估结束后统一展示。
- **作答与进度**：文字作答、逐题提交，展示题号与进度；每次作答即时落库，中途退出可恢复。
- **评估报告**：结束后生成总分与维度分（岗位理解、项目深度、技术基础、表达逻辑、STAR 完整性），逐题给出引用回答原文的亮点、问题与改进建议，标记高风险回答（答非所问、缺少量化、空泛、疑似夸大、逻辑跳跃），并给出 TOP 改进项；总评由模型生成，失败时使用本地模板。
- **评分执行**：题目全部追问结束后异步评分，不阻塞对话；结束报告时对未评分题目兜底补评，补评失败不影响报告生成。
- **结果联动**：报告可跳转到简历优化 / AI 定制；模拟结果不写回岗位匹配分，也不改变投递状态。
- **历史记录**：按岗位保存模拟记录，可恢复未完成的会话、回看报告，并与同岗位历史成绩对比趋势；同一岗位同时只保留一个进行中的会话。
- **边界**：以文字模拟为主，不做实时语音 / 视频面试；评价由 AI 生成，仅供参考，不代表真实面试结果，也不采集真实面试官信息。

### 2.12 校招信息库

- 公共只读校招岗位库，内置 12 条演示数据。
- 支持行业筛选、城市筛选、关键词搜索与分页。
- 展示岗位标题、公司、行业、城市、批次、截止日期与投递链接。
- **一键加入我的投递**：导入后生成待投递岗位，列表标记已导入，避免重复导入。
- 可通过校招采集流程补充新岗位（见 2.13）。

### 2.13 校招信息采集

- **关注公司管理**：维护公司名称、招聘官网域名、目标毕业届别、启用状态；同一用户下公司不可重复关注。
- **官网域名发现**：按公司名定向搜索，推荐招聘官网候选域名供用户确认。
- **采集流程**：按 `site:` 定向搜索官网 → 抓取页面 Markdown → DeepSeek 抽取岗位与招聘项目时间线 → 生成候选。
- **候选审核**：采集结果先进入待审核草稿，支持编辑、单条确认、单条驳回、批量确认；确认后才写入信息库。
- **去重与更新**：按公司 + 岗位标题 + 批次匹配已有候选；重复采集时，截止日期、开放日期、投递链接发生关键变化会重置为待审核，描述等非关键字段仅更新不触发复核；模型漏抽的字段不会覆盖已有值。
- **手动采集**：支持单家采集与「全部采集」，返回搜索数、抓取数、新增 / 更新 / 无变化数与结果消息。
- **定时采集**：默认每天 07:30（Asia/Shanghai）自动遍历所有启用公司，相邻公司间隔 2 秒以规避搜索限流；单家失败不影响其他公司；上一次未结束时自动跳过本次。
- **范围限制**：只采集岗位与招聘项目时间线，宣讲会、行程类活动不采集；发送的仅为公开网页内容，不涉及个人简历。

### 2.14 投递复盘

- **投递漏斗（5 级）**：全部岗位 → 已投递 → 进入笔试 → 进入面试 → 拿到 Offer。
- **环节转化率**：投递率、笔试率、面试率、Offer 率（按相邻环节计算）。
- 统计时结合岗位当前状态与历史求职事件，避免状态流转后遗漏环节。
- **近 6 个月投递趋势**：按月统计岗位新增数量。
- **平均匹配分**：已匹配岗位的平均分。
- **高频缺失关键词**：汇总历史 AI 匹配记录中未覆盖的 JD 关键词，按出现频次排序，展示前 6 个。
- **模拟面试统计**：展示已完成场次与平均模拟分，进行中的场次在卡片提示；可一键进入模拟面试。
- **自动复盘结论**：根据漏斗、匹配分与关键词分布生成文字建议，最多 5 条。
- 空数据状态引导先添加岗位并投递。

### 2.15 智能提醒

- 右上角铃铛展示未读数，每 60 秒刷新。
- **提醒类型**：
  - 今天 / 明天 / 后天的面试与笔试事件；
  - 3 天内截止的岗位（今天截止单独标记）；
  - 已过截止日期但状态仍为待投递的岗位。
- 按优先级（高 / 中）与时间排序。
- 支持单条标记已读、全部标记已读；已读状态按天重置，跨天后重新变为未读。
- 点击提醒条目跳转到投递列表，并按所属公司填入关键词搜索。
- 面试 / 笔试类提醒提供「去模拟」入口，直接进入该岗位的模拟面试。

### 2.16 个人中心

- **资料修改**：昵称、邮箱、毕业年份。
- **修改密码**：校验旧密码后更新，密码经 BCrypt 加密。
- **使用统计**：岗位数、简历数、匹配次数、优化次数。

## 3. 模块联动规则

| 触发动作 | 联动结果 |
|---|---|
| 新增 / 编辑岗位并填写截止日期 | 自动生成一条 DEADLINE 求职事件（当天 23:59），同步到台历、待办与提醒 |
| 修改 / 清空截止日期 | 先删除该岗位旧的 DEADLINE 事件，再按新值重建或不生成 |
| 岗位状态流转 | 自动写入对应事件：已投递 → APPLY，笔试 → WRITTEN_TEST，面试 → INTERVIEW，Offer / 未通过 → RESULT |
| 删除岗位 | 级联删除该岗位的求职事件与 AI 匹配记录 |
| 执行 AI 匹配 | 匹配记录入库，同时把匹配分回写到岗位 |
| 生成简历优化 | 优化记录入库，不修改简历 |
| 采用 AI 定制段落并生成版本 | 总是创建一份新简历版本，原版本保留，记录前后匹配分 |
| 确认采集候选 | 写入校招信息库，状态变为已确认 |
| 从信息库导入岗位 | 生成待投递岗位，并在信息库中标记已导入 |
| 生成的新简历版本 | 可在下次匹配、优化、定制与自动填充中直接选用 |
| 发起 AI 模拟面试 | 生成会话与评估报告，不修改岗位状态与匹配分 |

## 4. 功能边界与已知限制

- **私人自用定位**：已移除会员中心、免费福利、用户协议 / 隐私政策页面；不接入小程序、支付、扫码登录与微信登录。
- **AI 匹配与简历优化使用本地规则引擎**，不调用大模型、不上传简历内容；分数为规则计算，非语义理解。
- **AI 简历定制与校招采集依赖 DeepSeek**，需要服务端配置密钥；未配置时这两项功能不可用，其余功能不受影响。
- **自动填充不直接填写第三方网申表单**，仅做信息整理与复制，需用户自行核对粘贴。
- **扫描版 PDF / 纯图片简历无法解析文本**，需上传文字版 PDF / DOC / DOCX / TXT。
- **求职事件无手动管理入口**：事件由岗位截止日期与状态流转自动生成，不单独提供事件增删改界面。
- **定时采集为单实例设计**，通过原子标志防止任务重入；多实例部署不在当前支持范围。
- **校招信息库为公共只读数据**，用户侧只读与导入，写入统一走采集候选审核流程。
- **无团队协作、多用户共享、数据导出 / 备份功能**。
- **AI 模拟面试以文字进行**，不做实时语音 / 视频；评价由 AI 生成，仅供参考；不提供标准答案。
- **同一岗位同时只保留一个进行中的模拟面试**，需要重新开始时先完成或放弃上一场。
